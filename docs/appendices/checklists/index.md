# チェックリスト集

## ドキュメントレビュー観点

- [ ] 読者（誰が使うか）が明記されている
- [ ] 目的（何のために書くか）が明記されている
- [ ] 前提（環境/権限/依存）が明記されている
- [ ] 手順の再現性（成功条件/検証）がある
- [ ] 例外系・失敗時の分岐がある
- [ ] ロールバック判断がある
- [ ] 責任分界（誰が何をするか）がある
- [ ] 変更理由または変更不要理由が残っている
- [ ] 根拠、確認日、再確認条件が明記されている

## Runbook 完備性チェック

- [ ] 平常時の作業が定義されている
- [ ] アラートの初動（確認順）が定義されている
- [ ] 切り分けの観点（比較/変更点）がある
- [ ] エスカレーション基準がある
- [ ] 復旧/ロールバック判断がある
- [ ] 連絡先、エスカレーション先、外部窓口の最終確認日がある

## ポストモーテム品質チェック

- [ ] 個人攻撃になっていない（責任追及しない）
- [ ] 真因が「仕組み」として説明されている
- [ ] 再発防止が行動（誰が/いつまでに/何を）になっている
- [ ] 検知・手順の改善に反映されている
- [ ] follow-up Issue / PR と検証結果が紐づいている

## 監査メモ品質チェック

- [ ] 確認範囲と対象外が明確
- [ ] 判断に使った根拠が列挙されている
- [ ] 修正する項目と変更不要項目が分かれている
- [ ] 変更不要理由が「問題なし」で終わっていない
- [ ] 別 Issue に分離した項目のリンクがある
- [ ] 再確認条件と Owner が明確

## 文書保守チェック

- [ ] Owner が個人またはチームで明確
- [ ] 最終確認日と次回見直し日がある
- [ ] 外部仕様、連絡先、依存サービスの変更時に再確認する条件がある
- [ ] 公開ページや README から辿れる
- [ ] 廃止または統合する条件がある
